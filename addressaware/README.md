# Address-Aware PalmTree

This directory contains an address-aware extension to PalmTree that incorporates hierarchical address normalization into the pretraining process.

## Overview

Traditional BERT uses only token and positional embeddings. This implementation adds **address-aware positional embeddings** that encode three levels of hierarchical position information:

1. **Binary-level position** (bnorm): Where this instruction sits in the entire binary [0, 1]
2. **Function-level position** (fnorm): Where this instruction sits within its function [0, 1]
3. **Basic block-level position** (bbnorm): Where this instruction sits within its basic block [0, 1]

## Architecture

### Three-Level Embedding

```
Input: opcode(0xADDR:bnorm:fnorm:bbnorm) operands
         ↓
┌────────────────────────────────────────┐
│  1. Token Embedding                    │
│     - Standard vocabulary lookup       │
│     - Dimension: d_model               │
└────────────────────────────────────────┘
         ↓
┌────────────────────────────────────────┐
│  2. Address Positional Embedding       │
│     - Sin/cos(bnorm)  → d_model/3     │
│     - Sin/cos(fnorm)  → d_model/3     │
│     - Sin/cos(bbnorm) → d_model/3     │
│     - Concatenate & weight             │
└────────────────────────────────────────┘
         ↓
┌────────────────────────────────────────┐
│  3. Segment Embedding                  │
│     - For NSP task (0 or 1)           │
└────────────────────────────────────────┘
         ↓
    Sum & Layer Norm
         ↓
   Transformer Blocks
```

### Pretraining Tasks

1. **Masked Language Modeling (MLM)**: Predict masked tokens
2. **Next Sentence Prediction (NSP)**: Classify if two sequences are consecutive

## Data Format

Expects data generated by `cfg_address.py` and `dfg_address.py`:

```
opcode1(0xADDR1:bnorm:fnorm:bbnorm) operand1	opcode2(0xADDR2:bnorm:fnorm:bbnorm) operand2
```

Example:
```
mov(0x401008:0.022:0.296:0.444) rax qword [ rel addr_data(0x403fe8:1.000:0.000:0) ]
```

### Address Embedding Strategy

**Only tokens with address information get positional embeddings:**

| Token         | Has Position? | Position Values        | Reasoning                          |
|---------------|---------------|------------------------|------------------------------------|
| `mov`         | ✓ Yes         | (0.022, 0.296, 0.444) | Opcode with address info           |
| `rax`         | ✗ No          | (0.0, 0.0, 0.0)       | Regular operand (register)         |
| `qword`       | ✗ No          | (0.0, 0.0, 0.0)       | Regular operand (size specifier)   |
| `[`, `]`      | ✗ No          | (0.0, 0.0, 0.0)       | Syntax tokens                      |
| `rel`         | ✗ No          | (0.0, 0.0, 0.0)       | Regular operand (modifier)         |
| `addr_data`   | ✓ Yes         | (1.0, 0.0, 0.0)       | Address token with position info   |

**Rationale**: Only opcodes and explicit address tokens (addr_code, addr_data) carry structural meaning about where they are in the binary. Regular operands like registers, immediates, and syntax tokens are context-dependent and should not receive position embeddings.

This strategy:
- Reduces noise from irrelevant positional information
- Focuses the model on learning structural patterns from instruction locations
- Allows operand tokens to learn their semantics independently from position

## Usage

### 1. Prepare Data

Generate CFG and DFG data with address information:

```bash
cd /home/kun/Document/PalmTree/scripts
./generate_data.sh
```

This creates:
- `/home/kun/Document/PalmTree/data/cfg/all_cfg_combined.txt`
- `/home/kun/Document/PalmTree/data/dfg/all_dfg_combined.txt`

### 2. Build Vocabulary

```bash
cd /home/kun/Document/PalmTree/addressaware
python3 -m palmtree.dataset.vocab \
    -c ../data/cfg/all_cfg_combined.txt \
    -o vocab.pkl \
    -s 50000 \
    -m 3
```

### 3. Train Model

```bash
python3 train.py \
    --cfg_train ../data/cfg/all_cfg_combined.txt \
    --dfg_train ../data/dfg/all_dfg_combined.txt \
    --vocab vocab.pkl \
    --hidden 768 \
    --layers 12 \
    --attn_heads 12 \
    --seq_len 512 \
    --epochs 20 \
    --batch_size 32 \
    --lr 1e-4 \
    --mask_prob 0.15 \
    --nsp_prob 0.5 \
    --output_dir ./output \
    --cuda \
    --log_freq 100
```

### 4. Use Pre-trained Model

```python
import torch
from model import AddressAwareBERT, AddressAwareBERTForPretraining

# Load checkpoint
checkpoint = torch.load("output/best_model.pt")

# Create model
bert = AddressAwareBERT(vocab_size=50000, hidden=768, n_layers=12, attn_heads=12)
model = AddressAwareBERTForPretraining(bert, vocab_size=50000)
model.load_state_dict(checkpoint['model_state_dict'])

# Use for downstream tasks
model.eval()
```

## Key Features

### 1. Hierarchical Position Encoding

Instead of simple sequential position, encodes three levels:
- **Binary**: Global position in the entire binary
- **Function**: Local position within the function
- **Basic Block**: Fine-grained position within the block

### 2. Learnable Level Weights

The model learns to weight the three address levels:
```python
self.level_weights = nn.Parameter(torch.ones(3))
weights = torch.softmax(self.level_weights, dim=0)
```

### 3. Sinusoidal Encoding

Uses sin/cos encoding like standard positional embeddings but applied to normalized addresses:
```python
encoding[:, :, 0::2] = torch.sin(positions_scaled * div_term)
encoding[:, :, 1::2] = torch.cos(positions_scaled * div_term)
```

## Advantages

1. **Structure-aware**: Captures the hierarchical nature of binary code
2. **Position-agnostic**: Same instruction at different positions gets similar embeddings if structural role is similar
3. **Function-aware**: Understands relative positions within functions
4. **Block-aware**: Captures fine-grained control flow structure

## Training Tips

1. **Batch Size**: Start with 16-32, increase if you have more GPU memory
2. **Learning Rate**: 1e-4 to 5e-5 works well
3. **Warmup**: Use learning rate warmup for first 10K steps
4. **Sequence Length**: 512 is standard, reduce to 256 if memory constrained
5. **Masking**: 15% mask probability is standard BERT default

## Monitoring Training

The training script logs:
- Total loss (MLM + NSP)
- MLM loss and accuracy
- NSP loss and accuracy

Watch for:
- MLM accuracy should reach 60-70%
- NSP accuracy should reach 80-90%
- Loss should steadily decrease

## Extending

To use for downstream tasks:

1. Load pre-trained model
2. Add task-specific head (classification, similarity, etc.)
3. Fine-tune on task data

Example:
```python
class BinaryClassifier(nn.Module):
    def __init__(self, bert_model, num_classes):
        super().__init__()
        self.bert = bert_model
        self.classifier = nn.Linear(bert_model.hidden, num_classes)
    
    def forward(self, token_ids, segment_labels, binary_pos, function_pos, bb_pos):
        output = self.bert(token_ids, segment_labels, binary_pos, function_pos, bb_pos)
        cls_output = output[:, 0, :]  # [CLS] token
        return self.classifier(cls_output)
```
